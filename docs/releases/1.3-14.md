# Departs 1.3 (14) TestFlight

On 24 November 2026 the owner was asked whether to prepare the TestFlight build with iPad support as 1.2 (14) or as 1.3 (14). He chose 1.3 (14). This is the first Departs build for iPad.

The marketing version goes from 1.2 to 1.3 and the build number from 13 to 14. The upload waits for the owner's "ship": see [Archive and upload](#archive-and-upload).

## What changes since 1.2 (13)

- **iPad support** ([PR #48](https://github.com/p3ob7o/Departs/pull/48)), recorded as O25 to O27 and A52 to A60 in the plan's [seventh amendment](../plans/ios-two-screens.md#seventh-amendment-ipad-windows). Departs runs on iPad in one resizable window in all four orientations. In tall or narrow windows both screens stack the map above the list. A window wider than it is tall and at least 768 pt wide splits into equal halves: the map on the left, the controls and the list on the right. In a short stacked window the line map shrinks so that two departures stay visible under a long destination. iPhone stays portrait only.
- **One window** (O27). `UIApplicationSupportsMultipleScenes` is false. The setting applies to every device, including the iPhone Duo.
- **Destinations with a plus sign** ([PR #51](https://github.com/p3ob7o/Departs/pull/51)). The app now encodes a plus in a query as `%2B`, so a line to a destination such as "S+U Pankow" gets its departures from any host. The backend half of #51 reached production on 24 November 2026 and already repairs installed builds, 1.2 (13) included.
- **Backend hardening in this pull request.** When the line filter meets a departure without a line, or a provider name or direction that is not a string, it now leaves that departure out. With #51 alone, such a departure would have made every line request for that stop answer 500. No such provider response has been seen. The change reaches production when this pull request merges, and installed builds see no other difference.
- **Test-only changes**, not part of the app: the fixture server's log, which UI tests attach when they fail ([PR #47](https://github.com/p3ob7o/Departs/pull/47)), and the reworked Apple Maps hand-off test ([PR #44](https://github.com/p3ob7o/Departs/pull/44)).

## What to Test

Draft of the English testing notes:

> This is the first Departs build for iPad.
>
> On an iPad, open Departs upright and turned sideways. Upright, the map sits above the list. Sideways, the map fills the left half of the screen and the list the right half. Open a line, turn the iPad, and check that the same line stays open.
>
> Make the Departs window smaller, or put Departs next to another app. In a narrow window the map goes back above the list. Check that the line screen still shows its next departures under a long destination.
>
> In Berlin, open a line to a destination with a plus sign, such as "S+U Pankow". It should show its next departures, on iPhone and iPad.
>
> On iPhone, nothing else should look different.

## First build with iPad support

Every iPad check so far ran on simulators with the suite's local fixture server. These remain unverified:

- a physical iPad, with live transit data;
- an iPad with Wi-Fi only and no GPS, where location comes from Wi-Fi alone;
- a hardware keyboard and a pointer;
- VoiceOver speech on iPad;
- the iPhone Duo, which now also runs in one window and has never run a suite.
